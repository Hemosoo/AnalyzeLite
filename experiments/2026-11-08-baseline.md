# Baseline experiment: SmolVLM2-500M with uniform frame sampling (2026-11-08)

**Question.** How well does the unmodified baseline answer questions about short clips, and does giving it more frames help?

**Answer.** The model recognizes what is in a clip (95–100% on presence questions) but is at chance on when things happen. Going from 4 to 16 frames leaves accuracy flat (60% → 62% → 60%) while latency grows 3.5× and memory 2.2×.

## Setup

| | |
|---|---|
| Model | `HuggingFaceTB/SmolVLM2-500M-Video-Instruct`, float32, greedy decoding (deterministic) |
| Hardware | MacBook M1, 16 GB, macOS 13.7, PyTorch 2.8 on the Apple GPU (MPS) |
| Frame sampling | Uniform: the middle frame of each of N equal slices of the clip, in time order |
| Frame budgets | 4, 8, 16 |
| Clips / questions | 11 clips, 129 questions with ground truth, so 387 model calls in total |
| Metrics | Accuracy; end-to-end latency per question, including decoding and sampling frames; GPU memory; frame count |
| Code | `run_eval.py` (runner and scorer), `questions.csv` (ground truth), raw results in `2026-11-08-baseline.csv` |

**Scoring.** Each question lists its allowed answers (e.g. `yes|no`, `a|b`, `wallet|can`). The first allowed answer that appears in the model's output is its prediction. An output that mentions none of them counts as wrong.

## What the model receives

Decoded exactly from the model input for one question at 8 frames:

```
User: You are provided the following series of eight frames from a 0:00:12 [H:MM:SS] video.

Frame from 00:00:<fake_token_around_image><global-img>[64 image tokens]<fake_token_around_image>
Frame from 00:02:<fake_token_around_image><global-img>[64 image tokens]<fake_token_around_image>
… (one line per frame) …
Frame from 00:11:<fake_token_around_image><global-img>[64 image tokens]<fake_token_around_image>

Which object did I pick up first? A) wallet B) can. Answer with the letter.<end_of_utterance>
Assistant:
```

The pixel input is 8 frames of 3×512×512.

## Controls against leaks and bias

- **Nothing outside the video and question reaches the model.** No file names, no folder names, and no labels on frames. The timestamp labels in the images below exist only in these human-facing copies. Audio is not used.
- **Each question is a fresh single-turn prompt,** with no chat history.
- **Deterministic.** All 201 question × budget pairs repeated from an earlier run on the same day gave identical outputs.
- **Balanced answers.** Yes/no questions are 33 yes vs. 27 no. Letter questions have A correct 11 times and B 10 times.
- **Option order.** Every order question is asked in both option orders (21 pairs), so a model that always picks the same position gets at most one of each pair right.
- **Distractors.** Questions about absent objects (banana, green card) and about visible objects that never move (keyboard, the untouched can).
- **Baseline.** Each result is compared with an "always pick the first-named option" baseline. For yes/no questions that means always answering yes.

## Failure patterns (8 frames unless noted)

1. **It answers "is it visible?" instead of "did it happen?"** It rejects absent objects (banana and green card get "no", except one "yes" for the green card at 4 frames). But "Did I pick up the keyboard?" gets "Yes" on all 5 clips with a keyboard in view. "Did I pick up the can?" in the wallet-only clip, "Is a card removed?", "Does the person show a peace sign?" (thumbs clip) and "Does the hand show one finger?" (count-down clip) all get "Yes".
2. **No sense of start vs. end.**
   - "Is the cap on the bottle at the end?" → Yes (it was removed).
   - "How many fingers at the end?" (5 → 4 → 3) → 5.
   - "How many cards at the start?" (2 → 4) → 4.
   - "What is the last gesture?" → "Thumbs up" on both gesture clips, i.e. the first gesture. This holds at every budget.
3. **Order follows the prompt, not the video.** Only 3–5 of 21 order pairs are answered correctly in both option orders, the same as random guessing. "What did I pick up first?" in the bottle → wallet clip gets "wallet" at every budget.
4. **Counting fails.**
   - Objects picked up: "1" for both two-object can/wallet clips at every budget, and right for bottle → wallet only at 8 frames.
   - Four fingers → "5".
   - Cards added (2) → 4–5.
   - Number of different gestures → "10." in four of six cases.
5. **It reads text in the scene.** It sometimes answers "CELSIUS." (the brand on the can) instead of "can". That is scored wrong, and it cost one otherwise-correct answer at 4f and one at 8f.

## Takeaways

1. **More uniformly sampled frames are pure cost.** 4 → 16 frames: +0 points of accuracy, 3.5× latency (≈ +0.6 s per frame), 2.2× memory (≈ +0.3 GB per frame). On temporal questions the baseline is at chance at every budget. This is the gap the project targets.
2. **The model's strength is recognition, not temporal reasoning.** Approaches that hand it the right moments, or turn "when" questions into several "what" questions about specific moments, play to that strength. The [pilot on IMG_6524](2026-11-08-wallet-can.md) found that naive segment splitting alone was not enough when the object is small.
3. **Spatial detail is lost.** Every frame is squashed to 512×512 regardless of its 16:9 or 9:16 shape, which likely contributes to the finger-count errors (4 vs. 5) and the missed wallet.
4. **Frame decoding is a real share of latency.** About 1 s of the 2.9 s at 4 frames is spent decoding video on the CPU, before any model work. Any adaptive selection method must be timed end to end, including this step.
5. **Keep the bias controls.** Without the swapped option orders and the balanced yes/no questions, this baseline would look better than it is. On yes/no questions alone, "always yes" already scores 55%.

## Limitations

- Small sample: 11 clips and 129 questions, with 7–37 questions per type. Differences under ~15 points between budgets are within noise.
- Ground truth comes from the recorders' descriptions plus a review of the frames. Gesture names such as "open palm" were labeled from the frames.
- Scoring is literal. Synonyms and brand names ("CELSIUS") count as wrong, and 10 of 387 outputs were unparseable.
- Memory is the GPU allocator's total after each question, with its cache cleared before each budget. It includes cached blocks, so it is an upper bound on the true peak.
- The latency numbers are for an M1 Mac in float32, not a phone.
